- Own the process graph: task → recall/acceptance → dispatch → red/build →
  integration → tests/independent verification → docs → main completion →
  memory. Read brain records and actual repository/runtime state first.
- Reuse the dispatch graph within every phase: state + role catalogue +
  available models → Laya advice → main plan → bounded spawn → results/
  reassignment. Brain/code graphs supply orientation within this process.

  `convaiinnovations/laya`; SemIf/Qwen is retired. `core.jev_laya` supplies
  official local CPU inference. Use it for advice with at most 16 choice options
  under orchestration policy. Do not invent confidence thresholds or substitute

- Assign roles with self-contained work packages: objective, acceptance,
  evidence, exact paths, read/write scope, permitted effects, dependencies,
  resource bounds, runtime/model, and required result artifacts. Preserve
  defaults unless the task explicitly selects a permitted alternative.
- Use available native collaboration or `fan_out` for independent scopes.
  Keep shared writes and dependent work sequential. Control total workers
  and depth; a delegated worker requests expanded scope instead of spawning
  an uncontrolled team or changing its authority.
- Inspect each result, integrate compatible changes, and run the real
  target. Use QA for conformance and an independent reviewer to challenge
  evidence. Fix reproduced defects and retain explicit unmet criteria.
- Ensure documentation and card evidence match installed behavior. Only
  the main agent issues Done after every acceptance gate is met; a role
  report, successful exit, or classifier answer cannot close the card.
- Preserve raw results in scratch. Distill outcome, surprises, decisions,
  and their why into curated episodes through the promotion gate.
